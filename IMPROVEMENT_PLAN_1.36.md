# Open Repertory 1.36 improvement plan

1. Simplify provider branding in routine screens to “Open Repertory source”. Keep book names, clinical data, source identity and recorded grades intact. Keep original attribution and licences in a separate Legal credits view.
2. Fix recurring login: encrypted remembered approval lasts at most 30 days from a verified decision, supports phone reboot using wall/elapsed time and rollback checks, and migrates only still-valid legacy approval. Android device unlocking remains required. First sign-in, explicit sign-out, expired approval, account mismatch and authoritative access denial still require access verification.
3. Fix startup latency: after device unlock, valid remembered approval opens the clinical workspace immediately. Online checks run quietly. Persist authentication cookies, and treat network/server/session-restoration failures as unverified refreshes rather than deleting valid approval. Such failures never extend its expiry. Actual pending/rejected/revoked decisions close access immediately. Offline/expired-service-session revocation cannot be instantaneous; the remembered approval is bounded to 30 days.
4. Show Today and saved-case analysis before loading the full repertory. Preserve the full existing database and guard early search, source switching and loading failures. Measure startup and test delayed/failing responses and selection races.
5. Run adversarial cache/receipt tests, installed Android upgrade and session tests, browser clinical/branding/Materia Medica regression and signed-package integrity checks. Publish only after relevant checks pass. Keep the five latest releases automatically.

Implementation findings: source switching and early Library access needed null-safe statistics and book-bound indexing. The legal-notice loader needed a retry-safe button reference. An invalid local approval must close native record reads synchronously on resume. Explicit sign-out also needs a bounded draft-flush wait and persistent-cookie removal. These fixes are part of the release validation.
